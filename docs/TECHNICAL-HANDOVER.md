# Technical handover

## Architecture
```
Browser ──► Next.js 16 App Router (Vercel)
             ├─ (site) public routes — ISR (revalidate 1h) + on-demand revalidation
             ├─ /admin — dynamic, session-protected dashboard (server components + server actions)
             ├─ /api/enquiry, /api/mira, /api/admin/media, /api/admin/enquiries/export
             ├─ /media/{id}/{name} — DB-backed media
             └─ proxy.ts — optimistic redirect for /admin and /preview
                         │
                         ▼
             Drizzle ORM ──► PostgreSQL (DATABASE_URL)  |  PGlite (local / demo)
```
- **Single source of truth.** Every public page reads from the database through `src/lib/content.ts` (React `cache()` per request). Nothing a manager edits is hard-coded in components.
- **Revalidation.** Every admin mutation calls `refreshSite()` → `revalidatePath("/", "layout")`, so published changes appear on the next request. Pages are prerendered at build and regenerated on demand.
- **Theme.** `settings.theme` is converted to validated CSS custom properties in the root layout (`src/lib/theme.ts`); Tailwind tokens (`bg-red`, `text-heading`, …) map to those variables, so a colour change propagates everywhere.
- **Page builder.** Pages store an ordered `sections` JSON array. `src/lib/sections.ts` defines each block's fields and defaults (used by the admin); `src/components/sections/Sections.tsx` renders them with fixed, responsive layouts.

## Data model (`src/db/schema.ts`)
| Table | Purpose |
|---|---|
| `segments` | Five product segments (code, families, technologies, FAQs, images, SEO, status, order) |
| `products` | One record per product — canonical `code`, slug, segment, family, content, specs (with status), images, flyer, quote profile, availability, verification, SEO, status, scheduled `published_at` |
| `industry_sectors`, `industries` | Sector grouping and industry records (sub-industries, challenges, FAQs, images, catch-all flag) |
| `product_industries` | **Many-to-many** product ↔ industry with context, relevance and order |
| `product_relations` | Related products |
| `pages` | CMS pages and homepage (`slug = home`) with section JSON |
| `posts`, `post_categories` | Knowledge centre |
| `resources` | Downloadable documents |
| `media` | Uploaded files (bytea) and registered bundled assets, alt/credit/licence/stock flags, private flag |
| `enquiries`, `enquiry_notes` | Leads, per-product specs, files, status, assignment, notes/history |
| `redirects` | Managed 301/302 redirects with hit counts |
| `settings` | `site`, `theme`, `navigation`, `footer`, `seo` JSON |
| `users`, `sessions` | Staff accounts (role enum), hashed sessions, MFA |
| `revisions`, `audit_logs` | Snapshot per save; who/what/when |

Migrations: `drizzle/` (generated by drizzle-kit) embedded into `src/db/migrations.generated.ts` and applied at start-up by `src/db/migrate.ts` (transactional, advisory-locked). The first boot seeds content from `src/db/seed/*` (`src/db/seed.ts`).

## Key flows
- **Industry discovery** — `getDiscoveryData()` builds a serialisable snapshot (industries with ordered product IDs, product cards with derived material/application groups from `src/lib/taxonomy.ts`). `components/industry/Discovery.tsx` filters client-side (segment, product type, material, application, search), syncs filters to the URL and supports multi-select into the consolidated enquiry tray (`components/client/selection.ts`, browser storage — convenience only).
- **Enquiries** — `QuoteEngine` (multi-product, profile-dependent fields from `src/db/seed/quote.ts`) → `POST /api/enquiry` → `handleEnquiry()`: honeypot, timing, optional Turnstile, rate limit, server-side validation against the same field definitions, files stored as private media, enquiry row inserted, then optional email (Resend) and CRM webhook; outcomes logged on the record. The visitor sees success only after the database insert.
- **MIRA** — `src/lib/mira.ts` builds an approved knowledge base from published records (5-minute cache). With `ANTHROPIC_API_KEY`: Claude with structured JSON output; links are filtered to an allow-list of site URLs. Without a key (or on error): deterministic guided retrieval over the same data.
- **Admin writes** — `src/lib/admin/entities.ts` (Zod validation, permission check by status, slug uniqueness, relationship rewrites, automatic redirects, revision snapshot, audit, revalidation); settings in `settings-actions.ts`; media in `lib/admin/media.ts`.
- **Auth** — `src/lib/auth/*`: scrypt passwords, hashed session tokens, RBAC matrix (`rbac.ts`), `requireUser()` for pages (redirect/403), `authorize()` for actions, TOTP.

## Testing
`npm run test:build && npm run test:e2e` — 35 Playwright tests on a fresh in-memory database: the 15 backend acceptance tests (segment/product/industry CRUD, mapping add/remove, homepage hero, brand colour, article, PDF replace, enquiry management, URL redirect, role restrictions, draft privacy, archive/delete safety, mobile dashboard), public journeys A–G on desktop and mobile, SEO artefacts, 404, and horizontal-overflow checks at 360–2560 px.

## Extending
- New section type: add to `SectionType` (`db/types.ts`), define fields/defaults in `lib/sections.ts`, render in `Sections.tsx`.
- New entity field: schema → `npm run db:generate` → add to the Zod schema in `lib/admin/entities.ts` and the form tab in `lib/admin/forms.ts`.
- Object storage: replace the bytea path in `lib/admin/media.ts` / `app/media/...`.
